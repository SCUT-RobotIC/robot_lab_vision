# 27dog 轮足 URDF 与当前 RC 四足 URDF 的对比审查

审查日期：2026-10-11。长度单位为 m，角度为 rad，质量为 kg，惯量为 kg·m²，关节力矩为 N·m，关节角速度为 rad/s。FL/FR/RL/RR 分别表示左前、右前、左后、右后。

## 1. 审查对象、方法与结论边界

### 1.1 实际使用的基线

以代码实际引用为准，当前 Isaac Lab 使用的是 [dog.urdf](<../source/robot_lab/data/Robots/RC/dog urdf/urdf/dog.urdf>)，路径由 [rc.py](../source/robot_lab/robot_lab/assets/rc.py) 的 `RC_CFG.spawn.asset_path` 指定。Teacher 和 TS 配置均加载 `RC_CFG`。

本次主要对比 [27dog.SLDASM.urdf](<../source/robot_lab/data/Robots/RC/27dog urdf/urdf/27dog.SLDASM.urdf>)。另外检查了同目录的 [.urdf.bak](<../source/robot_lab/data/Robots/RC/27dog urdf/urdf/27dog.SLDASM.urdf.bak>)、[导出 CSV](<../source/robot_lab/data/Robots/RC/27dog urdf/urdf/27dog.SLDASM.csv>)、STL、控制器 YAML、package.xml、launch 和 export.log，区分原始导出与后续改动。

仓库还有 `RC/DOG/urdf/DOG.urdf`、`RC/rc_description/urdf/DOG.urdf` 和 `RC/dog urdf v2/urdf/dog urdf v2.urdf`，它们不是当前 `RC_CFG` 的输入。Sim2sim 默认读取 `RC/DOG/mjcf/rc_low_bar.xml`，属于另一路模型，不能代替本次基线，也不会因修改 27dog 自动更新。

### 1.2 已执行的检查

- XML 解析、全部 link/joint 字段与树结构检查，按机械角色映射名称后比较；数值容差使用 1e-9，避免把负零或导出尾数当成设计变化。
- 检查全部 16 个新关节的类型、父子连接、origin、axis、limit；检查全部惯性块、visual、collision、顶层 Gazebo 扩展及导出配套文件。
- 读取两套相邻目录中的二进制 STL 顶点与包围盒；另检查旧 URDF 的 `package://rc_description/meshes/...` 解析候选资源，比较轮轴、尺寸、网格单位、碰撞体包络，以及髋部/大腿网格的双向最近点距离。
- 检查旧版 18 个、新版及备份各 17 个惯量矩阵的正定性和主惯量三角不等式。
- 用当前初始关节角做正向运动学，计算足/轮接触高度、轮距与整机质心；检查现有任务、执行器、动作和观测的适配问题。

**这是静态模型审查，尚未启动 Isaac Sim/Isaac Lab/ROS，也未进行实机测量。** “文件一致”“几何吻合”和“物理真实”是不同结论：一致的参数仍可能继承旧模型误差；导出日志报错也不能自动证明 URDF 中某个字段错误。

### 1.3 总体判断

**27dog 应保留轮足结构和新版轮胎/小腿几何，但不能直接替换当前模型进行训练。** 最直接的阻断是 16 个关节的 limit 全部为零、轮关节还被定义为有限转动关节、现有任务只控制 12 个腿关节且仍按旧 link 名称查找足端。原有 12 个腿关节的轴向、安装位置和零位姿态未发现新的差异，不建议凭镜像直觉翻转右侧轴向。

| 类别 | 事项 | 处理判断 |
| --- | --- | --- |
| 明确需要修正 | 16 个关节的 lower/upper/effort/velocity 全零 | 恢复腿关节的有效约束；轮子单独定义连续旋转与真实输出端能力 |
| 明确需要适配 | 16 个 link 从 `*_link` 改成 `*_joint`，现有 foot 正则不再命中 | 优先恢复原有 link 命名；否则全面更新 body 查询 |
| 明确需要适配 | 轮关节没有对应执行器、动作或速度观测 | 独立定义轮电机控制；旧 12 维策略不能直接作为完整轮足策略 |
| 明确需要适配 | 默认基座高度 0.38、默认腿角直接沿用 | 理想平地上轮胎约穿地 0.04235；重设高度或腿角并验证 reset |
| 建议保留 | 原有 12 个腿关节的 origin、axis、零位约定 | 与实际基线一致，保留并做单关节实机方向确认 |
| 建议保留 | 轮轴 +Y、轮半径 0.06、宽度 0.025、左右横向偏置 | 有 STL 支持，保留；碰撞中心可从 ±0.0332 精调到 ±0.03315 |
| 建议保留 | 新的小腿与轮胎网格、机身包络修正 | 确实符合轮足结构；碰撞体仍需检查过包络与相邻重叠 |
| 必须复核后定稿 | 当前质量/质心/惯量与原始导出差别大 | 需要部件清单、质量标定和组合惯量，不能整体回退 CSV |
| 必须确认机械方案 | 独立 lidar link 被删除 | 实机仍装则恢复；已拆除或确实合并才保留删除 |
| ROS 打包修正 | 包名 `27dog.SLDASM` | 改为例如 `rc27_description`，并同步 mesh URI、launch、CMake、package.xml |
| 次要配套修正 | YAML 首项空字符串；Gazebo 扩展被删 | 清理 YAML；Gazebo 参数按实际使用场景重建 |

## 2. 原始导出与当前 27dog 文件不是同一层数据

27dog 当前 URDF 与其 .bak 的 robot 名称、visual、全部关节及树连接一致；变化集中在**全部 17 个惯性块和全部 link 的 collision**。备份的 collision 是 17 个 STL mesh，当前文件则是 25 个基本几何碰撞体。这是后处理/人工编辑的证据，不能把这些修改全部归因于 SolidWorks 导出器。

| 数据版本 | 总质量 | 特征 | 可信使用方式 |
| --- | ---: | --- | --- |
| 当前使用的 dog.urdf | 18.9905 | 已有腿关节限位、简化碰撞、lidar 和小腿辅助 link | 作为运动学、命名和既有仿真配置基线；不等于实机真值 |
| 27dog 当前 URDF | 20.9228 | 旧机身/髋质量被保留，小腿/轮质量增加，碰撞已简化 | 轮足候选模型；后处理的质量与惯量来源需确认 |
| 27dog .bak 与 CSV | 9.3043990078 | 原始 CAD 质量、mesh 碰撞、关节 limit 全零 | 用于追踪导出与部件归属，不宜整体恢复成训练模型 |

CSV 与 .bak 的 17 个质量、质心、惯量块一致。原始机身只有 3.68856 kg，髋部约 0.08033/0.09407 kg，大腿约 0.83858 kg；当前文件分别调整为 7.4172、0.9753、1.697 kg。CSV 部件清单包括 RS03 电机，而髋总质量仍非常小，提示材料密度、简化零件质量或质量覆盖可能不完整；这只是可疑证据，不能据此确定正确质量。

export.log 记录于 2026-09-24，出现 17 条 `Link.Joint.ChildLink.link` 未写入 CSV 的错误。实际 URDF 的 16 个 joint 均有 parent/child，形成唯一根 `base_link` 的完整无环树；**本次没有发现 URDF 父子关系缺失**。日志报错影响 CSV 字段，应修复导出流程，但不能把 URDF 的现有 child 全部判错。

### 4.1 轮轴是否正确

四个轮 STL 的旋转圆面位于 XZ 平面，轮宽沿 Y 分布，半径约 0.060000002。因此新版 `axis="0 1 0"` 与四轮几何吻合，碰撞 cylinder 通过 `rpy="pi/2 0 0"` 将默认 Z 轴转到 Y 方向，方向符号不影响圆柱几何。

在 hip=0、轮轴水平、平地无滑动时，接触点相对轮心位于 -Z，+Y 轴正转使轮胎底部相对轮心速度为 -X，所以车体前进 +X 对应四轮同号正角速度，近似 `omega = vx / 0.06`。右侧电机安装方向或编码器符号不同，应在硬件映射中处理；不能仅因左右镜像就把右轮 URDF 轴翻转。

### 4.2 限位必须恢复，但不要混用两层能力参数

27dog 的 16 个关节均为 `revolute`，且全部写成 `lower=0, upper=0, effort=0, velocity=0`。这些是明确的无效运动参数，不是“无限位”。不同导入器和执行器对零 effort/velocity 的处理可能不同，但 lower=upper=0 已与腿部运动及现有初始姿态直接矛盾。

若腿机械限位和坐标约定没变，先从实际基线恢复下列值，再按轮足结构的机械干涉测试修订。旧数值是现有参考，尚未实测证明为新版真实安全范围。

| 四腿关节类型 | 基线 lower | 基线 upper | 约合角度范围 | 基线 effort / velocity |
| --- | ---: | ---: | --- | --- |
| hip | -0.9773843811168246 | 0.9773843811168246 | -56° ~ +56° | 53.5 / 11 |
| thigh | -1.0471975511965976 | 4.1887902047863905 | -60° ~ +240° | 53.5 / 11 |
| calf | -2.8012534494508987 | -0.7417649320975901 | -160.5° ~ -42.5° | 53.5 / 11 |

当前实际执行器 `rc.py` 又分别设置 hip 的 effort/velocity=20/30，thigh 和 calf=30/10。**URDF 参数与训练执行器参数本来就不一致，不能把 53.5/11 称为当前所有仿真电机的最终能力。** 导入后应读取实际关节限制与执行器限制，确认所用版本如何组合它们，再统一输出端参数。保留当前腿 PD 配置只能作为迁移起点。

四轮应在机械允许无限转动的前提下定义为 `continuous`，不给有限的位置上下限；effort、velocity 按轮电机和减速器**输出端**能力填写。不能套用腿电机的 53.5/11，也不能臆填一个轮电机数值。如机械存在电缆缠绕或实际行程约束，才用有真实范围的 `revolute`。

两份主文件均没有 joint dynamics、calibration、safety_controller、mimic 和 transmission。它们不是本次新丢失的字段。Isaac Lab 当前由 Python 定义执行器、摩擦/armature 等参数；未来如果接入 ROS control，再按控制方案补充 transmission 和硬件接口。轮足腿部存在连杆传动时，仍需确认电机角/力矩与 calf 等效角/力矩的映射，不能把外观连杆全部视为同一刚体后就假定等效动力学自动正确。

轮子原始导出为 mass=0.185021367582257，ixx=izz=0.000252104048168579，iyy=0.000487105973266107，交叉项约 1e-19。当前把 ixx/izz 舍入为 0.0003，增幅约 19.00%；iyy 舍入为 0.0005，增幅约 2.65%。建议保留原始高精度轮质量、CoM y=±0.0320681433124501 及惯量，不必将所有惯量压缩到四位小数；x/z 极小尾数和交叉项可归零。

对 calf 做了进一步条件检查：**假设 .bak 中的 CAD 小腿刚体被完整保留，当前值只是再加入电机等缺失质量**，通过质量一阶矩和平行轴定理扣除原始小腿后，可反推出新增质量约 0.229368 kg。FL/RL 新增 CoM 约 (-0.000698, 0.040954, -0.273947)，但反推新增刚体的主惯量约为 (-0.00007444, -0.00001308, 0.00004909)，存在负值；FR/RR 同样出现负主惯量。因此当前 calf 参数**不满足“原 CAD 小腿 + 一个物理合理的新增质量”的简单组合解释**。

这个结果依赖“原始 CAD 质量正确且原刚体全部保留”的假设，不能直接证明当前总张量错误；如果原始密度本来错误，直接相减没有部件物理意义。它仍是需要重算 calf 的强证据，不能仅增加质量、挪动 CoM、手调几个惯量数值后就认定模型已标定。

建议按最终刚体归属重新建立部件账目：小腿本体、轮电机定子/减速器壳体、支架归 calf；轮胎/轮毂及随轮转动的部分归 wheel；RS03 等部件按实际随哪个 link 运动归属，避免跨 link 重复。合并时同时计算总质量、质量加权 CoM、各部件张量旋转与平行轴平移；只有全部四项一致才可定稿。

### 6.2 mesh URI 与 ROS 包名

当前 dog 的 visual URI 为 `package://rc_description/meshes/...`，而输入文件在 `dog urdf` 目录，其 package.xml 的包名是 `dog`。这是旧版已有的 URI/包身份不一致。仓库实际 `rc_description/meshes` 包含腿部对应 STL，但没有 `lidar_joint.STL`；因此如果使用标准 ROS 包解析，旧 lidar URI 会有资源风险。Isaac importer 是否按相邻 mesh 目录回退，需要在所用版本检查，不能因本地有文件就认定 URI 正确。

27dog 的 17 个 URI 改为 `package://27dog.SLDASM/meshes/...`，其对应 STL 全部存在，包名与 package.xml/CMake/launch 相互一致。但是该包名以数字开头、含大写和点，不符合 REP-144 的包名规范。建议将包身份统一为 `rc27_description`，并同步所有 URI、`project(...)`、`$(find ...)` 和元数据。robot 的显示名与 ROS 包名是两个概念，不能只改 `<robot name>` 就认为完成包修正。物理目录名可以另外整理，但目录改名本身不会解决包身份问题。

新 URDF 必须引用新版 calf/wheel 网格，不能为了让路径能解析就将它们指回旧 `rc_description` 下的脚垫 STL。

### 7.2 大腿/髋简化包络仍有遗漏

新版 thigh 两个碰撞体覆盖检查中，约 26.4% 的三角形顶点出现次数落在包络外；髋部约 3.4%~3.6%。这只是对网格表面的非均匀采样统计，不是体积比例，不可用作定量质量估计或简单评价碰撞模型好坏。

有代表性的几何风险是：左大腿 STL 的 y 最小达到 -0.0991，两个新版碰撞体的 y 最小约 -0.036；右侧对应 y 最大 +0.0991。若这些未覆盖的侧向结构会接触横杆或地面，需要给它们补独立简化碰撞体，或有依据地扩展局部包络。部分结构可能已由邻接 hip 的包络覆盖，需要在组装姿态下判定，不能只凭单 link 局部遗漏就一律加大。

当前 base box 的上表面从 0.0675 改为 0.0760（升高 8.5 mm）、下表面从 -0.0675 改为 -0.0592（升高 8.3 mm）。新版 box 匹配新版相邻 STL，会改变低杆任务的接触阈值，应复核横杆高度与奖励。第 6.1 节所述 URI 候选 base 还含更高的几何，因此这项修正不能单独证明已覆盖最终实机的全部上部结构。

### 7.3 小腿末端与轮胎的包络重叠

左 calf 末端 box 的 y 范围约 [-0.01295,0.04015]，轮胎范围 [0.02065,0.04565]，两者横向包络交叠约 0.0195 m，且 XZ 范围也交叠。直接把轮 STL 变换到 calf 坐标后，每个左轮约 3287/5550 个、右轮约 3160/5550 个三角形顶点出现次数落入末端 box。**这里证明的是简化碰撞体重叠，不是实机零件真的互相穿插。**

当前 `rc.py` 设置 `enabled_self_collisions=False`，相邻重叠不会在该配置下直接产生自碰撞力。但将来启用自碰撞或使用其他模拟器时需要对 calf-wheel 直接相邻对做过滤，或拆分/收紧末端包络，不应打开全机器人自碰撞后将其引发的弹跳误判为控制器问题。

另一方面，末端 box 可能填充实际结构空隙并与地形接触，需在多个腿姿态下确认它不会抢先成为支撑点。新版所有 calf 顶点均被覆盖不意味着包络已经最优。

## 8. lidar 与 Gazebo 扩展的删除

### 8.1 lidar

旧 lidar 固定在 base 上 `origin=(0.119,0,0.066)`，质量 0.2909，CoM=(0.0002,0.0005,0.0199)，惯量为 0.0002 的各向同性对角阵。新版没有独立 link、joint、网格或 collision。

如果实机仍装同一 lidar 且安装位置未变，建议恢复整个固定组件，并将网格复制到新资源包、修正 URI。如果实机取消或移动，则按最终安装方案更新。新版 base 的 mesh 包围盒没有增加到原 lidar 安装后的高度；这不足以证明是否漏装，但不能在没有部件证据时假定雷达已经合并到机身。

现有 height_scanner 绑定 `base_link`，是任务虚拟传感器，lidar link 被删并不直接导致该扫描器失效；质量、真实碰撞外形和后续硬件 TF 仍需要正确建模。

### 8.2 Gazebo

旧版 20 个 Gazebo 块包括：四个固定 feet joint 的 `disableFixedJointLumping=true`；四个 hip 和四个 thigh link 的 mu1/mu2=0.2；四个 calf 和四个 feet link 的 mu1/mu2=0.6；thigh 的 self_collide=0，calf/feet 的 self_collide=1；thigh/feet 还设置 kp=1000000、kd=100。新版全部删除。

轮关节改为可动关节后，固定足关节的禁止合并标记没有必要恢复。当前 Isaac Lab 在 `rc.py` 中启用接触传感器，并在任务中随机化材料/摩擦；不能只凭 Gazebo 参数消失就判定训练接触或摩擦丢失。若还要在 Gazebo 使用，应针对新版 link 名称、轮胎与车体材料、自碰撞过滤重建参数；不能原样复制旧 feet 参数和 self_collide 开关。

初始 z 可先取约 0.42235 加少量间隙，作为这一姿态、这一平地的验证起点；训练的 reset 地形高度、姿态随机化和弹性接触还要另外考虑，不能将此值当成所有任务的固定高度。也可重新优化腿角使较低目标高度可实现。该几何结果在修复关节限位后才能代表可用的仿真初态。

轮 joint 原点位于安装轴线上，轮实际几何中心在 y=±0.03315；更新 foot/wheel reward 时必须决定使用 link 原点、几何轮心还是接触点，不能三者混用。

## 10. 修正优先级与验收步骤

### 10.1 P0：接入模型前完成

1. 恢复 12 个腿关节的有效限位，确认机械仍适用；四轮按实际旋转约束定义 continuous，并填写实际输出端力矩/速度参数。
2. 保留现有 12 个腿 joint 名称、origin、axis 和零位；恢复可兼容的 link 名称，或同步修改全部 body 选择器。
3. 统一有效资源包身份与 17 个 mesh 路径，确认导入后的视觉/碰撞确实使用新版 STL。
4. 为四轮建立明确执行器、动作和状态观测；检查腿/轮选择互不混淆，修正轮子位置类惩罚和正常滚动奖励。
5. 重设初始高度/腿角；读取导入后的 DOF、实际限位、body 名称、执行器覆盖，确认没有轮胎初态穿地。

### 10.2 P1：训练前完成

1. 实称整机/部件质量，确认各 link 的质量归属；重点重算 calf 的 CoM 和惯量，保留轮惯量有效精度。
2. 确认 lidar 安装方案，恢复或有依据地合并/删除整块质量、惯量、视觉和碰撞。
3. 检查 thigh/hip 的未覆盖结构与 calf-wheel 简化包络重叠；通过最终姿态下的接触可视化定稿碰撞模型。
4. 在挂起机体、逐关节小幅正角测试中，确认四髋、四大腿、四小腿和四轮运动方向；实机电机编号/零偏/符号另建映射。
5. 平地静置、自由下落、直线滚动、制动和低杆碰撞检查；确认支撑来自四轮，正常滚动不会被误判滑动/非期望接触。

### 10.3 P2：工具链与维护

- 控制器 YAML 中的首项空字符串应清理，输出明确的 12 腿 + 4 轮映射。新版已增加四轮条目，但 YAML 本身不会为 Isaac Lab 创建执行器。
- 原始 CAD/CSV/.bak 保留为追溯材料，训练用经过校准的 URDF 单独维护。后续再导出时，将限位、命名、碰撞简化、质量标定等作为可重复的处理步骤，避免覆盖修复结果。
- 修复导出器的 CSV child 字段写入，增加字段级核对；导出成功提示不能代替 limit/axis/质量审查。
- 在真正使用的 Isaac 环境强制重新生成 USD；修改 STL 后尤其检查缓存。[convert_urdf.py](../scripts/tools/convert_urdf.py) 已提供 `force_usd_conversion=True` 的转换入口，可据实际场景选择无导入驱动、速度驱动等设置。导入默认驱动与后续执行器参数必须对应。
- ROS/Gazebo 如继续使用，重建轮胎材料、自碰撞过滤和控制接口；同时更新对应轮足 MJCF/部署配置。

### 10.4 最小验收标准

修正版本应满足：唯一 base 根、完整树连接；12 个腿关节有有效位置限位、4 个轮有符合机械的旋转类型；全部有动关节轴为单位向量；全部资源可解析；4 个轮 body 被接触传感器/奖励正确选中；所有实际需要驱动的 DOF 被执行器覆盖；初态无地面穿透；质量/惯量有可追溯依据；四轮同号命令前进方向与实机映射一致。

在 USD/模拟器中核对这些标准之后，才可进行长时间训练。文档中的连续关节、恢复旧限位、初始高度和轮控制建议尚未直接修改源 URDF 或现有训练配置。
